# Testing and Validation

## Current CI-equivalent validation

Run:

```bash
pytest tests/ -v --tb=short
```

This is the exact test command currently used by `.github/workflows/ci.yml`.

## Useful local checks

```bash
python3 -m compileall -q app
python3 -m json.tool .zed/settings.json >/dev/null
python3 -m json.tool .zed/tasks.json >/dev/null
git diff --check
```

Only run JSON checks when `.zed/settings.json` and `.zed/tasks.json` exist.

## Current test coverage facts

Current tracked tests cover:

- `/auth/login` success, invalid credentials, and missing required fields.
- `/releases/` listing behavior.
- `/releases/{release_id}` found and not-found behavior.
- `/releases/{release_id}/validate` valid and blocked-release behavior.

Current tests do not cover:

- `verify_token` directly.
- Expired token verification directly.
- Protected release endpoints, because current release endpoints are not protected.
- Database persistence, because current runtime does not use a database.
- Production Dulvarn release decision semantics.

## Do not claim absent tooling

Do not claim validation from Ruff, mypy, security scanners, Docker builds, coverage gates, migrations, deployment checks, or production integration tests unless those tools are explicitly added and run.

## Generated artifact cleanup

After validation, remove only local artifacts generated by validation if created:

- `.pytest_cache/`
- `__pycache__/`
- `*.pyc`
- temporary virtualenv created specifically for validation

Never use broad `git clean` without explicit user approval.
